# 실제 사진·CAD 검증 절차

현재 목표는 설비 반입·설치 전 공간 검토입니다. CAD 편집기나 설치 가능 여부를 보증하는 시스템은 아닙니다.

## 1~6번 작업 상태

1. 실제 고객 사례 검증: 사진·도면과 실측 기준값을 받은 뒤 진행합니다. 현재 검증 자료는 가상 설비와 합성 도면입니다.
2. 화면 개편: 청색·회색 계열과 자료 등록, 배치 검토, 확인 항목, 검토서의 작업 순서를 적용했습니다.
3. 사진 설비 등록: 사진과 직접 입력한 치수, 모델명·출처로 등록하고 재배치합니다. 사진만으로 정밀 3D를 생성하지 않습니다.
4. 확인 체크: 담당자·확인일·출처와 치수·정비공간·돌출물 확인을 기록합니다. 치수나 자료 변경 시 관련 확인을 해제합니다.
5. 검토서: 사진·확인 기록·변경 내역을 저장된 검토 기준으로 출력합니다.
6. 도면 입력 감소: 지원하는 DXF 엔티티와 3D 메시에서 객체 후보를 추출하고 사용자가 확인한 뒤 등록합니다.

## 자료를 받으면 확인할 것

1. 새 프로젝트를 만들고 실제 현장 폭·깊이·천장·문·측정일을 입력합니다.
2. 사진 설비는 알려진 폭·깊이·높이를 함께 입력합니다. 부착물·제어반·컨베이어는 구성요소로 보완합니다.
3. CAD는 사용 단위와 상향 축을 확인합니다. DWG는 지원 엔티티로 단순화한 DXF로 내보내고, 3D는 GLB/STL/OBJ를 사용합니다.
4. 추출 후보와 원본을 대조합니다. 빠진 벽·기둥, 하나로 합쳐진 기계, 잘못 분리된 부품, 제외 내역을 확인합니다. DXF 높이와 선의 두께는 직접 보완합니다.
5. 알려진 치수와 좌표 3개 이상을 대조하고 설비를 이동·회전해 기존 작업과 충돌 결과를 비교합니다.
6. 미확인 항목을 담당자가 확인하고 검사 기록을 저장합니다. JSON 복원과 PDF 검토서의 사진·치수·출처를 대조합니다.

잘못된 단위, 누락된 장애물, 실제와 다른 형상은 검사 정확도에 직접 영향을 줍니다. 자동 분류는 이름에 따른 제안이며 정밀 형상 인식이 아닙니다. 검사는 직육면체 외곽 기준이고, 반입 경로 전체·하중·배관·전기 검토는 포함하지 않습니다.

## 재현 가능한 브라우저 점검

`npm test`, `npm run build` 후 `npm run preview`를 실행합니다. Playwright와 Microsoft Edge가 있는 환경에서 `node tests/browser-smoke.cjs`를 실행합니다. 별도 설치된 Playwright는 `PLAYWRIGHT_MODULE`에 모듈 경로를 지정합니다. 캡처·PDF·JSON은 임시 폴더 또는 `INSTALLCHECK_EVIDENCE_DIR`에 기록합니다. 테스트는 별도 브라우저 프로필을 사용합니다.
