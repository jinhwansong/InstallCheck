# InstallCheck

산업설비의 최종 사양과 현장 치수를 맞춰보는 **단일 사용자 로컬 우선 프로토타입**입니다. 설비를 본체·컨베이어·제어반 등 여러 직육면체로 구성하고, 배치 및 공간 검토의 근거를 저장합니다.

## 실행

Node.js 22.18 이상 또는 24 LTS가 필요합니다.

```sh
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소를 엽니다. 배포 결과를 확인하려면:

```sh
npm test
npm run build
npm run preview
```

`preview`의 기본 주소는 `http://127.0.0.1:4173`입니다. 개발 서버의 기본 주소는 `http://127.0.0.1:5173`입니다. 주소가 달라지면 브라우저 저장 공간도 달라집니다. JSON 내보내기/불러오기로 이동하세요.

## 사용

1. 기본 가상 프로젝트에서 설비와 기둥 간섭을 확인합니다.
2. **설비**에서 본체·컨베이어·제어반의 크기, 로컬 좌표, 바닥 높이를 수정합니다.
3. 설비를 왼쪽 마우스로 드래그하거나 X/Z 값을 변경합니다. 회전 각도는 숫자로 입력합니다. 빈 화면 드래그는 시점 회전, 휠은 확대/축소입니다.
4. **현장**에서 구역 치수, 천장, 문 치수, 실측일, 판정 여유와 장애물을 편집합니다. 비어 있는 천장·문·실측일은 미확인입니다.
5. **검사 기록 저장**으로 입력값과 결과를 보존합니다. 이후 치수나 현장이 바뀌면 재검토 필요가 표시됩니다.
6. **검토 이력**에서 저장된 결과를 선택합니다. 3D 화면은 현재 작업을 표시하며 과거 입력값은 검토서에 포함됩니다.
7. **검토서 출력**의 브라우저 인쇄 창에서 PDF로 저장합니다. 선택된 검토 또는 가장 최근에 저장된 검토를 출력하며, 미저장 현재 상태를 자동으로 보고서에 대입하지 않습니다.
8. **JSON 백업**으로 자료를 보관하고 **불러오기**로 복원합니다. 파일의 저장된 결과는 지원되는 검사 규칙으로 재계산합니다.

위치의 X/Z는 현장 원점 기준, Y는 바닥에서의 높이입니다. 구성요소 X/Z는 설비 원점 기준 중심, Y는 구성요소 하단 기준입니다. 로컬 +Z가 전면입니다. 50 mm 스냅은 마우스 이동에만 적용합니다.

## 구현 범위

- 복수 설비 및 구성요소 추가·복제·삭제, 장애물 편집
- 수평 회전(OBB/SAT)과 높이를 반영한 구성요소 간 접촉·충돌 검사
- 현장 경계, 천장·상부 여유, 보수적 외곽 정비공간, 지정 자세 문 치수 비교
- 미확인·주의·문제·기준 충족 상태와 설비 위치 포커스
- 저장된 입력값 스냅샷, 변경 감지, 되돌리기/다시 실행
- 브라우저 저장, JSON 검증·복원, 인쇄용 PDF 보고서
- 외부 CDN·분석·AI·CAD API 없이 번들 내에서 실행

## 적용 한계

정밀 CAD 형상 검사가 아닙니다. 입력되지 않은 돌출물·형상·현장 조건을 알 수 없습니다. 구성요소는 yaw 회전만 지원하며 기울기·곡면·형상 빈 공간·문 개방 궤적을 계산하지 않습니다. 동일 설비 내부의 구성요소끼리의 접촉은 검사 대상이 아닙니다.

작업·정비공간은 구성요소 전체를 감싼 외곽 상자를 확장하여 보수적으로 검사합니다. 분리된 공간에서 과도한 경고가 발생할 수 있습니다. 문 검사는 설비의 **로컬 폭 방향**과 높이 비교이며 문 위치·복도·회전/분해 반입·운반장비를 검사하지 않습니다. 하중·배관·전기·구조·안전 인증을 지원하지 않습니다. 최종 설치 가능 여부는 현업 담당자가 확인해야 합니다.

## 데이터와 보안

자료는 해당 브라우저의 localStorage에 저장됩니다. 계정·서버·조직별 권한·저장 암호화·위변조 방지·자동 서버 백업이 없습니다. 개발 실행은 로컬 인터페이스로 제한되어 있습니다. **고객의 민감한 실데이터를 공동 서비스에 넣기 위한 운영 보안이 완성된 상태가 아닙니다.**

다른 탭이 같은 저장 공간을 바꾸면 자동 저장을 중지해 덮어쓰기를 방지합니다. 읽기 실패 시 기존 값을 자동으로 초기화하지 않고 복구 다운로드를 제공합니다. 브라우저 정리·프로필 삭제·시크릿 모드 종료 시 자료가 사라질 수 있으므로 JSON을 별도로 백업하세요. 데이터가 많아 저장 한도를 넘으면 저장 실패 안내에 따라 백업해야 합니다. 로컬 기록과 JSON은 변경 가능하므로 감사 인증 자료가 아닙니다.

입력 제한: 설비 40개, 설비당 구성요소 30개, 전체 구성요소 250개, 장애물 100개, 검토 이력 30개, 가져오기 5 MB. 치수는 최대 100,000 mm, 판정 여유는 0~500 mm입니다. 한도 초과 시 조용히 잘라내지 않고 오류를 표시합니다.

## 클라우드·사내 설치

`npm run build`로 생성된 `dist/`를 일반 정적 웹 서버에서 제공할 수 있습니다. 사내 서버에서도 같은 빌드를 사용할 수 있습니다. 로컬 외부 호스트에서 실행할 때는 HTTPS가 필요합니다(`crypto.randomUUID`). 클라우드에 정적 파일을 올려도 프로젝트가 서버에 저장되거나 사용자 간 공유되는 것은 아닙니다.

공동 사용 제품으로 확장할 때는 서버 저장, 인증·조직/프로젝트 권한, 암호화와 키 관리, 감사로그, 백업/복구, 보존·삭제 정책 및 고객 보안심사를 추가해야 합니다. 폐쇄망에서 배포할 파일은 빌드 결과이며 실행 중 외부 API가 필요하지 않습니다. Node/npm 설치와 최초 패키지 확보는 별도 준비가 필요합니다.

## 구조

- `src/model.ts`: 데이터 형식, 엄격한 JSON 검증, 스냅샷과 변경 감지
- `src/inspection.ts`: 단위 mm의 순수 검사 함수
- `src/scene.ts`: Three.js 표시·선택·이동
- `src/main.ts`: 편집·검사·저장·복원·보고서 흐름
- `src/styles.css`: 반응형 화면과 인쇄 스타일
- `tests/core.test.ts`: Node 기본 테스트 러너 기반 동작 검증

개발·검증 범위와 결과는 `docs/implementation.md`, `docs/verification.md`를 참조하세요.
